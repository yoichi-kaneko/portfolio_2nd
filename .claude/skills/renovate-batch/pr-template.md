# PR 本文の形式

手順 11 で作る PR 本文の雛形。次の点に従って埋める。

- 根拠の示し方、判定の基準、外部の PR・issue やユーザーへのメンションを避けるルールは
  [shared/writing-rules.md](../renovate-pr/shared/writing-rules.md) に従う。
- このリポジトリの PR への参照 `#<番号>` は、「取り込んだ PR」「外した PR」の表の先頭列にだけ書く。
  手順 11 の確認では、表の先頭列以外にある `#<番号>` を外部への参照として検出する。
- これらの表の先頭列以外には、リンクやリリースノート・CHANGELOG の文言を書かない。手順 11 の
  PR・issue への参照の確認は、先頭列が `#<番号>` の表の行を検査から外すので、そこに紛れ込んだ外部への
  参照を検出できない。
- グループ化された PR で複数のパッケージを更新する場合は、パッケージごとに行を分け、2行目以降の
  先頭列にも同じ `#<番号>` を書く。
- `<…>` は実際の内容に置き換える。当てはまらない行や節（外した PR が無い、除外を追記していない、
  など）は削除する。

```markdown
## 概要

Renovate が作成した次の PR の依存関係の更新を、1本にまとめて適用する。マージ後、取り込んだ PR は
Renovate の次回の巡回で自動的に閉じられる。

<Renovate 以外のコミットがある PR を取り込んだ場合: ただし、`<pkg>` を更新する PR は Renovate 以外のコミットがあり、Renovate が自動では閉じないので、マージ後に手で閉じる>

**総合判定: <低 / 中 / 高>**

### 取り込んだ PR

| PR      | パッケージ | 変更                | 種類                    | 区分                                                                         | 判定           |
| ------- | ---------- | ------------------- | ----------------------- | ---------------------------------------------------------------------------- | -------------- |
| #<番号> | `<pkg>`    | `<旧版>` → `<新版>` | <patch / minor / major> | <dependencies / devDependencies / packageManager / Node.js / GitHub Actions> | <低 / 中 / 高> |

### 外した PR

| PR      | 理由                                                                                          |
| ------- | --------------------------------------------------------------------------------------------- |
| #<番号> | <メジャー更新のため別に処理する / 公開から1日未満 / 検証が失敗した / base 側で別に更新された> |

外した PR は Renovate の PR として残る。

### パッケージごとの調査

#### `<pkg>` <旧版> → <新版>

- **主な変更**: <リリースノートの要点>
- **破壊的変更・非推奨**: <なし / 内容>
- **このリポジトリへの影響**: <使用箇所（`src/...`）と照合した結果。使用箇所が無ければその旨>
- **参照**: [リリースノート](<リリースの URL>) / [差分](<compare の URL>)

### 実施した作業

- `<base>` から作業ブランチを作り、取り込んだ PR の版の書き換えを適用
- `.pnpmfile.mjs` を適用して `pnpm-lock.yaml` を生成
  - Renovate は `.pnpmfile.mjs` を実行しないため、元の PR では `pnpmfileChecksum` の欠落と
    `readPackage` フックの未反映により、CI の `pnpm install --frozen-lockfile` が失敗していた
- `pnpm-workspace.yaml` の `minimumReleaseAgeExclude` に `<pkg>@<版>` を追加（公開から1日未満のため）

### ローカル検証

| コマンド                         | 結果          |
| -------------------------------- | ------------- |
| `pnpm install --frozen-lockfile` | <成功 / 失敗> |
| `pnpm lint`                      | <成功 / 失敗> |
| `pnpm test`                      | <成功 / 失敗> |
| `pnpm build`                     | <成功 / 失敗> |

E2E は CI で検証する。

<Node.js のメジャーを上げた場合: ローカル検証は Node.js <ローカルの版> で行った。新しい版での検証は CI に任せる>
```
