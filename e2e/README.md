# E2E テストの規約とカバー範囲

このディレクトリでは、Next.js を実際に起動し、ブラウザで利用者の操作と画面の連動を検証する。
以下は本変更で追加・整備したケースを含む、維持すべきカバー範囲である。機能や仕様を変更したときは、対応するテストとこの文書を同じPRで更新する。

## 実行方法

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm test:e2e
# デスクトップ / モバイルのみ
pnpm test:e2e --project=chromium
pnpm test:e2e --project=mobile-chromium
# ファイルやケースを絞る
pnpm test:e2e e2e/home-interactions.spec.ts
pnpm test:e2e --grep 'Lightbox'
# レポート / UI
pnpm exec playwright show-report
pnpm test:e2e:ui
```

- デスクトップは Desktop Chrome、モバイルは Pixel 7 相当の Chromium エミュレーションで実行する。実機・WebKit・Firefoxでの動作保証ではない。
- `mobile.spec.ts` はモバイル専用。それ以外の spec はデスクトップで実行する。
- ポート3001はE2E専用。既存サーバーを再利用せず、競合した場合は失敗させる。通常の開発サーバーは別ポートで起動する。
- `support/start-server.mjs` が必要なOS環境変数だけで Next.js の開発サーバーを起動する。認証情報は空文字で上書きし、`.env*` から実サービスの値が補充されるのを防ぐ。
- 本番ビルドの成功は `pnpm build` で別途検証する。通常のE2Eは開発サーバーに対する検証であり、本番配信環境の検証とは区別する。
- ローカルは2並列、CIは1並列。テスト全体は60秒、通常の assertion は10秒。ローカル再試行は0回、CIは2回。失敗時はスクリーンショットとtraceを保存する。

## 新規ケース・変更時の規約

### ユーザー操作と期待結果

- `test` と `expect` は必ず `./fixtures` からimportする。Playwrightの型だけは `@playwright/test` からimportしてよい。
- ケース名は「条件 / 操作 / 期待結果」が分かる日本語にする。正常系に加え、その機能で意味のある取得中・失敗・境界・復帰操作を検討する。
- 実際の `click` / `tap` / キー入力を使う。Reactの状態やイベントハンドラーを直接呼んで、E2Eの操作確認の代わりにしない。
- フィルタは件数の減少だけで成功にしない。対象が含まれ、対象外が含まれないことを確認する。詳細は見出しの存在だけでなく、選択内容との対応を確認する。
- データ一覧の期待値には `data/*.json` を利用できる。ただし、検証対象のフックや変換関数を呼んで期待値を生成しない。
- 開く / 閉じる操作には可能な範囲でキーボード、フォーカス復元、背景操作への影響も含める。小さい画面に特有の操作はモバイルspecに置く。

### API・画像・音声の境界

- 共通fixtureで GitHub / 登山レポート / Cloudinary のアプリAPIを既定の成功レスポンスに差し替える。個別ケースは `page.route` で必要なエンドポイントだけ上書きする。
- モックの型・配列順・値域を実APIの契約に合わせる。GitHubは `W1 → W5` を返し、UIが逆順にする。
- Cloudinary画像本体もfixtureで応答する。縦長800×1200、横長1600×900のSVGを使い、実Cloudinaryには接続しない。ローカルの主要画像はモックせず、実際のNext画像配信を検証する。
- Google MapsはE2E用環境変数で無効化する。一覧・詳細・前後移動は実UIで検証するが、地図タイル・マーカー・pan / zoomの実SDK連携はこのスイートの保証範囲外。
- 音声は `support/audio.ts` でAudio要素の再生・停止・終了・拒否を制御する。実MP3の音質・配信・CORSやブラウザ固有の自動再生制限は保証しない。
- Vercel Analytics / Speed Insightsは空のスクリプトを返す。計測イベントの送信は対象外。
- 未定義のAPIや外部接続を許可してテストを通さない。新しい依存を追加する際は必要なモックを明示する。
- ブラウザのrouteはサーバー側通信を遮断しない。実サービスを使うサーバー処理の検証は、別の統合テストと専用環境で行う。フォント取得などNextのビルド・起動に必要な通信まで完全オフラインにする設定ではない。

### 待機とassertion

- `getByRole` とアクセシブルネームを優先する。名前が重複する要素はダイアログ・セクション・詳細領域にスコープする。`data-testid` は一覧や描画状態など適切なロールがない対象に使う。
- `waitForTimeout` による固定待機、`force: true` による操作不能の隠蔽を避ける。Playwrightの再試行付きassertionや `expect.poll` を使う。
- API待機は遷移・操作の前に登録する。取得中の確認にはレスポンスを保留するgateを使い、`finally` で必ず解放する。
- 初期表示とエラー表示が同じ場合は、表示だけで失敗処理を検証したことにしない。生成画像は500応答と `aria-busy=false` を確認する。
- `toBeVisible()` は画像のロード成功、opacity、画面内・クリップ領域内表示を保証しない。用途に応じて `naturalWidth > 0`、computed opacity、`toBeInViewport`、座標を確認する。
- 時計に依存するケースは遷移前にPlaywright Clockを設定する。時間を跨ぐケースは時計を止めてから進め、実時間の経過を待たない。時計の数字を無条件に固定して通常時刻のE2Eを増やさない。
- ブラウザ時計とサーバー時計を混同しない。フッターはServer Componentで現在年を生成するため、E2E起動時の `TZ=UTC` に合わせた現在年を期待する。
- 他ケースの結果や実行順に依存しない。共有の可変状態を置かない。

## 他のテストとの分担・対象外

- Vitest: 時刻判定の全境界、配列・データ検証、フックの全分岐、APIハンドラーの応答、Redisキャッシュや外部APIの例外処理を検証する。
- E2E: 実際のDOM・CSS・フォーカス・スクロール・ページ遷移を通して、ユーザー操作が複数コンポーネントの表示に正しく伝わることを検証する。
- 単体テストの全組合せをE2Eに複製しない。例えば時刻境界は代表的な1境界の自動表示更新をE2Eで守り、純粋な判定表は単体テストで守る。
- 外部サービスの稼働確認、Google Maps実SDK連携、実音声配信、実機・全ブラウザ、ピクセル単位のビジュアル回帰、包括的なアクセシビリティ監査、本番環境固有の動作は本スイートのカバー範囲に含めない。
- 不足しているUI仕様をテストのskipや弱いassertionで隠さない。実装が必要なときはテストと一緒に修正し、PRに理由を記載する。
